# Разделение главы оснащения — v7

По замечанию пользователя большой непрерывный зелёный блок разделён на самостоятельные смысловые части.

1. Белое вступление: заголовок слева, объяснение и действие справа. На телефоне естественный порядок сверху вниз.
2. Светлая панель рабочих зон: тёмным остаётся только поле чертежа. Переключатели, пояснение, основа и результат размещены на бумаге. На desktop рисунок и пояснения рядом; на телефоне последовательно.
3. Отдельная бумажная полоса «Что входит в проработку»: четыре результата и три этапа. Визуально отделена от схемы.
4. Компактное белое продолжение про столы, мойки и стеллажи.

Палитра, Manrope, контент, все четыре зоны, aria-pressed и переход к запросу сохранены. Новые изображения и утверждения о компании не добавлялись.

До изменения при 1920px высота planning составляла 1351px, затем шёл такой же тёмный neutral293px. На 390px —1832px и 338px соответственно. После: planning936px, отдельный process343px, neutral210px; на 390px —1106px, process691px, neutral302px. Высота всей последовательности уменьшилась умеренно, а площадь зелёного сокращена до отдельного поля рисунка, без обрезания текста.

20 браузерных утверждений прошли:6 ширин 1920/1440/1024/768/390/320 без горизонтального переполнения; светлый основной фон; переключение 4 зон;4 результата и 3 этапа; CTA; отсутствие ошибок JavaScript. npm run check, npm run build, git diff --check прошли. Скриншоты и JSON: output/playwright/v7/.

Два независимых предварительных assessment: layout_v7_assess подтвердил необходимость группировки и сокращения непрерывной тёмной области; layout_v7_scan выполнил единственный detector --scope layout.0 сигналов, degraded regexfallback из-за отсутствия парсеров. Это ограниченная автоматизация, не сертификат качества. Реальные устройства, другие движки и полный скринридерный аудит не проверялись.

Финальное независимое ревью: ship, материальных исправлений не требуется. Проверены 12 снимков текущего состояния и 2 исходных снимка v6.
